# 输出契约

当 Phase 4 或其他场景需要生成结构化 QA 资产时，读取本文件。

## 必需文件

输出文件名必须使用 `系统名 + 指引`。不得使用日期前缀、英文临时名或版本号作为主文件标识。

| 文件 | 命名 |
|---|---|
| 总设计文档 | `系统名_总设计文档.md` |
| XMind 导图 | `系统名_XMind导图.md` |
| 结构化载荷 | `系统名_结构化载荷.json` |
| 测试资产 | `系统名_测试资产.xlsx` |

如果需要版本信息，应放在文件正文、元数据或子目录中，不得覆盖主文件名的人类可读业务语义。

## Excel 工作簿

通过 pandas/openpyxl 使用 `openpyxl` 或 `xlsxwriter` 写入。中文资产不得依赖本地默认编码。

必需工作表：

| 工作表 | 名称 |
|---|---|
| Sheet 1 | `测试用例库` |
| Sheet 2 | `需求跟踪矩阵` |

可选工作表：

| 工作表 | 名称 | 触发条件 |
|---|---|---|
| 可选 | `代码追踪矩阵` | 当 Phase 5 输出 `code_traceability` 行时生成 |

必需格式：

- 表头行加粗。
- 表头行填充背景色。
- 开启自动筛选。
- 冻结首行。
- 自动调整列宽。

## 测试用例列

测试用例表必须使用：

| 列 | 含义 |
|---|---|
| 模块 | 必须使用系统名前缀 |
| ID | 唯一测试用例 ID |
| 子功能 | 必须使用系统名前缀 |
| 标题 | 推荐格式：`系统名_子功能_验证场景` |
| 优先级(P0-P3) | `P0` / `P1` / `P2` / `P3`，可在括号中补充说明 |
| 追踪编号 | 一个或多个 `R` / `T` ID |
| 前置条件 | 清晰的前置条件 |
| 步骤 | 可执行的 QA 操作步骤 |
| 预期结果 | 必要时必须区分视觉表现与后端/数据影响 |

## RTM 列

RTM 工作表必须使用：

| 列 | 含义 |
|---|---|
| 模块 | 模块名或系统模块名 |
| 追踪编号 | `R` 需求 ID 或 `T` 表字段 ID |
| 追踪类型 | 需求 / 表字段 / 代码 / 风险 / 其他 |
| 追踪描述 | 原子化追踪目标描述 |
| 测试用例ID | 关联测试用例 |
| 覆盖状态 | 已覆盖 / 部分覆盖 / 未覆盖 |
| 备注 | 歧义、风险或待跟进事项 |

## 代码与配置追踪矩阵列

当 Phase 5 产生后端源码与配置追踪信息时，可选的 `代码追踪矩阵` 工作表必须使用：

| 列 | 含义 |
|---|---|
| 需求ID | `R` 需求 ID |
| 表字段ID | `T` 表字段 ID；非表驱动时可为空 |
| 配置表路径 | 配置工作簿或 CSV 路径 |
| Sheet | 工作表名或 CSV/TSV 文件名 |
| 配置字段 | 配置字段或列名 |
| 配置值 | 命中值、样例值或范围摘要 |
| 默认值 | 默认值或空 |
| 边界值 | 最小/最大值、枚举边界、概率/权重摘要 |
| 配置风险 | 缺表、缺字段、空值、类型不匹配、溢出、重复、非法概率/权重 |
| 协议/入口 | 路由、协议 ID、RPC、Handler 或 Controller |
| 业务承载 | Service、Manager、Domain 或核心方法 |
| 数据承载 | 配置、DB、Cache 或状态字段 |
| 输出承载 | 回包、事件、日志、任务或异步回调 |
| 风险点 | 资源、并发、幂等、鉴权、重放、恢复、数值风险 |
| 测试用例ID | 关联测试用例 ID |
| 命中置信度 | `高` / `中高` / `低` |

## 结构化载荷 JSON

脚本使用以下结构：

```json
{
  "test_cases": [
    {
      "模块": "系统名-模块",
      "ID": "TC-001",
      "子功能": "系统名-子功能",
      "标题": "系统名_子功能_验证场景",
      "优先级(P0-P3)": "P0",
      "追踪编号": "[R1,T1]",
      "前置条件": "string",
      "步骤": "string",
      "预期结果": "string"
    }
  ],
  "rtm": [
    {
      "模块": "系统名-模块",
      "追踪编号": "R1",
      "追踪类型": "需求",
      "追踪描述": "string",
      "测试用例ID": "TC-001",
      "覆盖状态": "已覆盖",
      "备注": ""
    }
  ],
  "code_traceability": [
    {
      "需求ID": "R1",
      "表字段ID": "T1",
      "配置表路径": "C:/NuoYaIdle/Tools/表格配置及转换/excel/Item.xlsx",
      "Sheet": "Item",
      "配置字段": "consumeType",
      "配置值": "1",
      "默认值": "0",
      "边界值": "0/1/2",
      "配置风险": "",
      "协议/入口": "Handler.method",
      "业务承载": "Service.method",
      "数据承载": "配置/DB/Cache",
      "输出承载": "回包/事件/日志",
      "风险点": "string",
      "测试用例ID": "TC-001",
      "命中置信度": "高"
    }
  ]
}
```

脚本也兼容以下历史别名：

- `需求编号` or `关联编号` as `追踪编号`
- `需求描述` / `字段描述` / `需求/字段描述` as `追踪描述`
- `编号类型` as `追踪类型`
- `需求编号` as `需求ID`
- `字段ID` as `表字段ID`
- `表格路径` / `配置文件` / `配置表` as `配置表路径`
- `工作表` / `页签` as `Sheet`
- `字段名` / `配置列` as `配置字段`
- `字段值` / `命中值` as `配置值`
- `配置问题` / `配置缺陷` as `配置风险`
- `入口` / `协议` / `路由` / `RPC` as `协议/入口`
- `置信度` as `命中置信度`

## 脚本用法

先校验载荷：

```powershell
python "C:\Users\yangfeng\.codex\skills\game-qa-pipeline-data-vision-expert\scripts\validate_game_qa_payload.py" --input-json <json-path> --system-name <系统名>
```

再生成工作簿：

```powershell
python "C:\Users\yangfeng\.codex\skills\game-qa-pipeline-data-vision-expert\scripts\build_game_qa_data_vision_workbook.py" --input-json <json-path> --out <xlsx-path> --system-name <系统名>
```

## 编码规则

- 中文资产优先使用 `.xlsx`。
- 如果额外导出 CSV 旁路文件，必须使用 `utf-8-sig`。
- 不得使用本地默认编码导出中文 CSV。
