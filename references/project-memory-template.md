# 项目专属知识库

建立、更新或应用项目专属知识库时，读取本文件。

本文件同时承担两类职责：

- 当前项目的已确认项目记忆。
- 后续补充新项目记忆字段时的维护模板。

项目记忆用于黑盒风险预判和白盒审计范围识别。它不能覆盖当前需求文档、配置表证据、源码证据或用户在当前会话中的确认结论。若项目记忆与当前证据冲突，必须显式输出冲突并要求确认。

## 白盒审计默认认知

| 方向 | 默认认知 | 审计关注点 |
|---|---|---|
| 协议入口 | Facade 接口声明 + AbilityImpl 实现承载客户端请求 | 检查 `@MethodForClientOnly`、请求参数、权限校验、密码锁、业务 Manager 调用 |
| 资源变更 | 常通过 TPF 道具/物品/奖励消耗管理器完成 | 关注扣除与发放原子性、异常回滚、重复请求幂等 |
| 持久化 | TPF Entity/StorageSystem/Redis-MySQL 驱动组合 | 关注 dirty/save 时机、异步存库、掉线/重登恢复 |
| 缓存 | Redis、RedisCache、本地 Map/Caffeine 并存 | 关注缓存与 DB 一致性、过期/手动清理、跨服共享范围 |
| 配置 | 表格生成代码 + Apollo 动态配置并存 | 关注字段是否读取、值域是否闭合、配置和代码口径是否一致 |
| 消息 | 存在 Kafka 与 TPF 消息队列生产者 | 关注异步消息丢失、重复投递、消费幂等 |
| 跨服/位面 | 存在基于 Redis/gRPC 的有状态路由、服务状态组件，以及地图/全局/公会等多服务 | 关注切场景、跨服同步、远程 RPC、断线重连 |

## 更新规则

- 新项目记忆必须来源于用户确认或源码/配置/构建文件的直接证据。
- `待确认` 项不能作为确定性缺陷依据。
- 不围绕项目不存在的能力生成伪风险、伪反问或伪用例。
- 当前需求、源码或配置表与项目记忆冲突时，输出确认问题，不得静默选择。
- 任务收尾时总结 `本次规则增量`，并询问是否有新的避坑点需要加入资产库。
