# 核心资产库

当 Phase 0、Phase 1、Phase 3 或 Phase 5 需要使用项目记忆、历史坑点、风险探针或能力边界时，读取本文件。

## 项目术语

| 术语 | 含义 | QA 关注点 |
|---|---|---|
| `[CDC]` | 跨服逻辑中心，处理玩家跨服数据同步、结算及协议转发 | 跨服数据一致性、协议转发丢包、结算幂等 |
| `[原子性]` | 资源扣除与发货必须同时成功或失败 | 单边账、回滚、补偿、重复提交 |
| `[G1-道具]` | 装备类道具，不可叠加，拥有唯一标识 ID 和随机词条 | 唯一 ID、词条保留、资产复制 |
| `[G2-道具]` | 消耗材料类，可重叠 | 堆叠上限、分拆、溢出、负数 |
| `[GS/DS]` | 游戏服务器与数据服务器 | 异步存库、缓存一致性、失败恢复 |
| `[平滑扩容]` | 分线/位面自动开启机制 | 负载均衡、切线数据、玩家状态同步 |
| `[保底/大保底]` | 抽卡概率计数器逻辑 | 继承、重置、跨池、断线恢复 |
| `[Tick同步]` | 服务器逻辑帧率 | 碰撞检测、技能判定、帧间精度 |
| `[埋点/BI]` | 客户端行为记录 | 上报时机、重复上报、漏报 |
| `[冷启动/热更新]` | 整包启动与补丁更新 | Manifest、资源索引、版本兼容 |

## 历史坑点

| 坑点 | 典型风险 | 测试探针 |
|---|---|---|
| `[负数溢出]` | 输入框未检查最小值导致刷道具；代码级 `int32` 边界溢出 | 负数、0、最小值、最大值、超最大值 |
| `[连点竞态]` | 高频点击导致并发领取礼包；缺少防抖或分布式锁 | 高频点击、并发请求、重复提交 |
| `[强杀回档]` | 结算瞬间关闭进程导致数据不一致 | 强杀、断线、重登恢复、事务补偿 |
| `[溢出处理]` | 背包满时未发邮件补偿或直接丢失道具 | 背包满、邮件补偿、丢弃路径 |
| `[时区重置]` | 0 点任务重置因时区偏差失效 | 跨时区、夏令时、服务端时间 |
| `[状态机锁死]` | 引导中强制下线导致重登后操作卡死 | 生命周期恢复钩子、重登态 |
| `[跨服丢包]` | CDC 传送瞬间网络抖动导致装备丢失 | 跨服切换、RPC 超时、重放 |
| `[共享 CD]` | 多技能共用 CD 计时器导致释放冲突 | CD 复用、技能切换、冷却刷新 |
| `[UI 遮挡]` | 全屏弹窗下背景按钮仍可点击 | Z-Order、遮罩、穿透点击 |
| `[数值堆叠]` | 多重百分比 Buff 叠加导致溢出、负数或精度丢失 | 百分比叠加、截断、浮点精度 |

## 能力边界

| 能力边界 | 规则 |
|---|---|
| `[资产出口能力边界]` | 在审计未保存态、资源保护、资产流转时，必须先确认项目真实存在的资产出口能力。若项目不存在“邮件附件收发、装备分解、直接丢弃、NPC 售卖”等功能，则不得围绕这些能力生成反问、测试用例或伪风险。审计范围只覆盖项目实际存在的资产出口系统。 |

## 风险探针包

Phase 0 必须选择本轮启用的风险探针包。

| 探针包 | 适用场景 | 重点问题 |
|---|---|---|
| 原子性 | 资源扣除、奖励发放、交易、合成、重铸 | 扣除成功但发放失败、重复发货、回滚遗漏 |
| 状态机 | 引导、跨场景、跨服、战斗、活动结算 | 状态锁死、恢复入口缺失、非法跳转 |
| 保底算法 | 抽卡、掉落、权重、概率池 | 计数继承、重置、分母变化、概率总和 |
| 交易限制 | 背包、邮件、拍卖、兑换、资产出口 | 越权交易、重复提交、出口不存在导致伪风险 |
| 恢复链路 | 断线、重登、强杀、切服、切场景 | pending 状态、补偿、幂等 |
| 配置表一致性 | 表格驱动系统、后台配置、数值表 | 字段类型、默认值、空值、重复项、孤儿引用 |
| UI 穿透 | 弹窗、遮罩、全屏界面、层级切换 | Z-Order、点击穿透、焦点丢失 |
| 并发与重放 | 请求型功能、奖励领取、RPC | 幂等、锁、重放包、重复请求 |

## 用例规范

| 项 | 规范 |
|---|---|
| 系统名抽取 | 默认取需求主标题或用户明确确认的系统名称，例如 `暗金重铸` |
| 模块命名 | `[系统名]-[模块名]`，例如 `暗金重铸-主重铸界面与材料装配` |
| 子功能命名 | `[系统名]-[子功能]`，例如 `暗金重铸-功能开启` |
| 用例标题命名 | `[系统名]_[子功能]_[验证场景]` |
| 逻辑树命名 | Phase 2 的模块节点和功能点节点都必须带系统名前缀 |
| XMind 命名 | 根节点使用系统名；模块和功能点节点继续带系统名前缀 |
| 输出文件命名 | `系统名_指引`，例如 `暗金重铸_总设计文档.md` |
| 优先级 | `P0(核心流)`、`P1(重要/异常)`、`P2(次要)`、`P3(美化)` |
| 步骤要求 | 颗粒度适中，每步一个动词，前置条件必须明确 |
| 预期结果 | 必须区分视觉表现与后端数据库反馈 |
| 异常覆盖 | 每个功能点必须包含至少两条反向测试路径 |
